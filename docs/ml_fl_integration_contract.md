# SentinelFL — ML & Federated Learning Integration Interface Contract

This document specifies the exact interface contracts, data formats, and protocols established between the **Data Preparation & Ingestion Pipeline** (Frontend / FastAPI Backend) and the downstream **Centralized ML & Federated Learning (FL)** modules (developed by the teammate).

---

## 1. Processed Dataset Representation

Processed datasets are generated by the FastAPI backend (`app/services/preprocessor.py`) without data leakage. Cleaned and scaled flow records are represented as RFC 4180-compliant CSV files and memory-mappable NumPy matrices / Pandas DataFrames:

- **Matrix Dimension**:
  - Input Features $X \in \mathbb{R}^{N \times D}$, where $N$ is the number of flow samples and $D$ is the number of retained numerical and encoded features.
  - Target Vector $y \in \mathcal{C}^N$, where $\mathcal{C}$ contains the discrete attack/benign class names or integer mappings.
- **Data Cleanliness Guarantees**:
  - **Zero NaNs**: All missing values are imputed using the researcher's configured strategy (`median`, `mean`, `mode`, or row removal).
  - **Zero Infs**: All infinite values ($+\infty, -\infty$) resulting from division-by-zero flow rates are converted to NaNs and imputed before scaling.
  - **Zero Constant Features**: Columns with variance $\sigma^2 = 0$ (constant values across all samples) are automatically removed.
  - **Preserved Ground Truth**: The target column is never scaled, normalized, or used as an input feature during feature transformations.

## 2. Feature and Target Identification

The dataset metadata contract is exposed programmatically via the backend API:

- **Metadata Endpoint**: `GET /api/v1/preprocessing/jobs/{job_id}`
- **Global Contract Schema**: `GET /api/v1/preprocessing/contract`

```json
{
  "job_id": "099a4192-3329-4d37-88c2-4874b29bb882",
  "dataset_id": "c1f7a049-75f1-4df6-880c-0062bc627dd2",

    "packet_length",

  "target_classes": ["Benign", "Mirai", "Bashlite"],
```

### Ordering Guarantee
Downstream ML and Federated models must feed features in the **exact order** specified by `feature_names`. All categorical variables transformed by one-hot encoding are explicitly listed with their column prefix (e.g. `protocol_TCP`, `protocol_UDP`).

## 3. Train / Validation / Test Splits & Data Leakage Prevention

To prevent data leakage in both centralized and federated experiments:

1. **Split-First Protocol**: The raw dataset is partitioned into `train`, `validation`, and `test` subsets *before* computing statistical transformation parameters:
   - Default split ratio: $70\%$ train, $15\%$ validation, $15\%$ test (configurable by researcher).
   - Stratified sampling is applied when the target column is discrete to maintain class balance across splits.
2. **Strict Transformer Fitting**:
   - `RobustScaler` / `StandardScaler` / `MinMaxScaler` are fitted **exclusively on $X_{\text{train}}$**.
   - $X_{\text{val}}$ and $X_{\text{test}}$ are transformed strictly using the scaler fitted on $X_{\text{train}}$.
3. **Partition Access**:
   The teammate can download distinct split artifacts directly:
   - Full Processed: `GET /api/v1/preprocessing/jobs/{job_id}/download?split=full`
   - Training Partition: `GET /api/v1/preprocessing/jobs/{job_id}/download?split=train`
   - Testing Partition: `GET /api/v1/preprocessing/jobs/{job_id}/download?split=test`

## 4. Reusable Transformation State for FL Edge Clients

In Federated Learning, IoT edge clients often capture unnormalized network flows that must be preprocessed locally before feeding into the local neural network or decision tree.

The preprocessing pipeline records the transformation state:

```python
from app.schemas.contracts import PreprocessingTransformationState

state = PreprocessingTransformationState(
    scaling_method="robust",
    scaling_params={
        "packet_length": {"center": 64.0, "scale": 128.0},
        "packet_rate": {"center": 120.0, "scale": 220.0}
    },
    imputation_strategy="median",
    imputation_values={"packet_length": 64.0, "packet_rate": 120.0},
    categorical_encodings={"protocol": ["TCP", "UDP", "ICMP"]},
    dropped_columns=["flow_id", "timestamp", "src_ip", "dst_ip"]
)
```

Clients apply these identical parameters locally without sharing raw flow data with the central server.

## 6. How the Teammate Can Load Data in Python

```python
import pandas as pd
import requests

# 1. Fetch Job Metadata
JOB_ID = "your-preprocessing-job-id"
API_BASE = "http://localhost:8000/api/v1"
HEADERS = {"Authorization": "Bearer <YOUR_SUPABASE_ACCESS_TOKEN>"}

meta_res = requests.get(f"{API_BASE}/preprocessing/jobs/{JOB_ID}", headers=HEADERS)
metadata = meta_res.json()["result"]

feature_cols = metadata["feature_names"]
target_col = metadata["target_name"]

# 2. Download Training Split
train_url = f"{API_BASE}/preprocessing/jobs/{JOB_ID}/download?split=train"
train_df = pd.read_csv(train_url, storage_options=HEADERS)

X_train = train_df[feature_cols].values
y_train = train_df[target_col].values

print(f"X_train shape: {X_train.shape}, y_train classes: {set(y_train)}")
```

## 7. Model Registry & Evaluation Metrics Contract (`public.model_runs`)

When your training worker (centralized baseline or federated aggregation) completes execution, it records the run checkpoint in the existing Supabase `public.model_runs` table.

### 7.1 Database Table Schema (`public.model_runs`)
The existing PostgreSQL schema is preserved without alterations:

| Column | Type | Description |
|---|---|---|
| `id` | `uuid` | Primary key identifier for the model run |
| `model_name` | `text` | Human-readable model identifier (e.g. `RF-Baseline-CICIoT2023`) |
| `status` | `text` | Run state: `'staged'` \| `'training'` \| `'completed'` \| `'failed'` |
| `dataset_id` | `uuid` | Foreign key referencing `public.datasets(id)` used for training |
| `metrics` | `jsonb` | Structured evaluation metrics and training metadata |
| `created_at` | `timestamptz`| Timestamp when the run was initialized |
| `created_by` | `uuid` | Foreign key referencing `auth.users(id)` of the researcher |

### 7.2 Core Evaluation Metrics Specification
The `metrics` JSONB column contains genuine evaluation telemetry and architectural metadata. Downstream ML and FL workers must adhere to this standardized key structure:

| Metric Key | Type | Optional? | Valid Range / Unit | Missing Representation | Description |
|---|---|---|---|---|---|
| `accuracy` | `float` | **Yes** | $[0.0, 1.0]$ | Omitted or `null` | Test classification accuracy on test partition |
| `precision` | `float` | **Yes** | $[0.0, 1.0]$ | Omitted or `null` | Macro-averaged precision on test partition |
| `recall` | `float` | **Yes** | $[0.0, 1.0]$ | Omitted or `null` | Macro-averaged recall on test partition |
| `f1_score` | `float` | **Yes** | $[0.0, 1.0]$ | Omitted or `null` | Macro-averaged F1-score on test partition |
| `loss` | `float` | **Yes** | $\ge 0.0$ | Omitted or `null` | Evaluation loss (cross-entropy or log-loss) |
| `inference_latency_ms` | `float` | **Yes** | $\ge 0.0$ ms | Omitted or `null` | Single-sample batch average inference duration in milliseconds |
| `training_time_sec` | `float` | **Yes** | $\ge 0.0$ s | Omitted or `null` | Wall-clock training duration in seconds |

#### Additional Metadata Keys (Optional)
| Metadata Key | Type | Optional? | Description |
|---|---|---|---|
| `algorithm` | `string` | **Yes** | Architecture tag: `random_forest`, `logistic_regression`, `fedavg`, etc. |
| `version` | `string` | **Yes** | Model checkpoint version tag (e.g., `v1.0.0`) |
| `hyperparameters` | `object` | **Yes** | Key-value dictionary of model hyperparameters |
| `artifact_path` | `string` | **Yes** | Storage pointer or relative path to model checkpoint artifact |
| `features_used` | `string[]` | **Yes** | List of input feature column names used during training |
| `top_features` | `object[]` | **Yes** | Array of `{ "feature": string, "importance": float }` |
| `error` | `string` | **Yes** | Error message / traceback if the run failed (`status: "failed"`) |

### 7.3 Canonical `metrics` JSON Examples by Lifecycle Phase

#### A. Staged Run (`status: "staged"`)
Evaluation metrics have not yet been produced. They **must be omitted or set to `null`**. No fake numbers are inserted:
```json
{
  "algorithm": "random_forest",
  "hyperparameters": {
    "n_estimators": 100,
    "max_depth": 16
  }
}
```

#### B. Training In-Progress (`status: "training"`)
The training engine has begun training. Evaluation metrics remain uncomputed:
```json
{
  "algorithm": "random_forest",
  "progress_pct": 45.0,
  "current_epoch": 5
}
```

#### C. Completed Training Run (`status: "completed"`)
Genuine evaluation metrics computed strictly on the held-out test split $X_{\text{test}}$:
```json
{
  "accuracy": 0.9742,
  "precision": 0.9680,
  "recall": 0.9710,
  "f1_score": 0.9695,
  "loss": 0.0821,
  "inference_latency_ms": 4.25,
  "training_time_sec": 48.3,
  "algorithm": "random_forest",
  "version": "v1.0.0",
  "hyperparameters": {
    "n_estimators": 100,
    "max_depth": 16,
    "criterion": "gini"
  },
  "artifact_path": "models/centralized/rf_baseline_v1.joblib",
  "features_used": [
    "packet_length",
    "packet_rate",
    "byte_rate",
    "protocol_TCP",
    "protocol_UDP"
  ],
  "top_features": [
    {"feature": "packet_rate", "importance": 0.382},
    {"feature": "packet_length", "importance": 0.291},
    {"feature": "byte_rate", "importance": 0.185}
  ]
}
```

#### D. Failed Training Run (`status: "failed"`)
If an exception occurs during training or evaluation, the error is recorded; evaluation metrics are omitted:
```json
{
  "algorithm": "random_forest",
  "error": "MemoryError: Unable to allocate 16.0 GiB for array with shape (100000, 2048)"
}
```

### 7.4 Metric Field Rules & Missing Value Representation

1. **Zero Synthetic Values Guarantee**:
   - **Never** substitute default values (`0.0`, `-1.0`, or placeholder floats) for uncomputed metrics.
   - The frontend parser (`mapDatabaseRowToModel`) strictly checks `typeof rawMetrics[key] === 'number'`.
   - Any missing, null, undefined, or non-numeric value renders in the UI as a clean placeholder (`—` or `No eval metric`), never as a fabricated metric.
2. **Canonical Naming & Compatibility**:
   - The canonical naming convention for stored database JSON keys is standard `snake_case`:
     `accuracy`, `precision`, `recall`, `f1_score`, `loss`, `inference_latency_ms`, `training_time_sec`.
   - The frontend `mapDatabaseRowToModel` parser accepts both `snake_case` (`f1_score`, `inference_latency_ms`, `training_time_sec`) and legacy UI `camelCase` (`f1Score`, `inferenceLatencyMs`, `trainingTimeSec`), guaranteeing bidirectional compatibility without requiring database schema changes.
3. **Execution Status Integrity**:
   - **`staged`**: Run initialized; waiting for teammate's ML runner to pick up execution.
   - **`training`**: ML/FL worker has started fitting model weights.
   - **`completed`**: Training finished successfully, weights saved to `artifact_path`, and genuine evaluation metrics computed on $X_{\text{test}}$.
   - **`failed`**: Training or evaluation threw an unrecoverable exception (store error in `metrics.error`).
   - A run must **NEVER** be recorded with `status = 'completed'` or labeled as trained unless genuine execution confirmed successful completion.
